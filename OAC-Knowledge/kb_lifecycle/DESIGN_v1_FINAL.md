## 1. Quyết định kiến trúc đã chốt (ĐỔI so với v0)

### D1 — Phân loại tri thức: DERIVE, không hand-maintain manifest. *(đổi: bỏ `knowledge_map.yaml` đầy đủ)*
- **GENERATED** = file mang **banner** do builder phát ra (`# GENERATED by <script> | rebuild: raw/REBUILD.md | body_sha256:<hash> | do-not-hand-edit`). Không liệt kê tay.
- **CURATED/LOG** = một `kinds.yaml` NHỎ chỉ allow-list các file người viết (glossary, governance_register, live_query_recipes, playbook, CONFLICTS, fields/_*.md hand-written...) + binding schema.
- Validator rule: file có banner ⇒ generated ⇒ KHÔNG được nằm trong `curated`; file `curated` ⇒ KHÔNG có banner; **mọi file tracked phải phân loại được** (nếu không → FAIL "unclassified"). ⇒ AC "phủ 100%" được *cưỡng chế*, không *tuyên bố*.
- *Lý do:* manifest tay là nguồn-sự-thật-thứ-hai tự rot; tập GENERATED tính được từ builder. (reviewer-1)

### D2 — Anti-edit guard: HASH-IN-BANNER (+ rebuild-diff khi đã reproducible). *(đổi: bỏ "built_from changed?")*
- Guard tính `sha256(body trừ dòng banner)` so với hash trong banner. Hand-edit body ⇒ mismatch ⇒ FAIL. Không bịp được bằng cách "đụng source".
- Khi rebuild đã reproducible (sau Phase 0 + tracked extract snapshot): nâng cấp guard thành `rebuild → diff`, bắt cả "sửa cả source lẫn output".
- Pin `.gitattributes` (LF) TRƯỚC, nếu không hash sẽ nhiễu đa máy. (reviewer-1, V2)

### D3 — Phân loại đặt CO-LOCATED (front-matter/banner), external chỉ cho cái không tự-mô-tả-được.
- `kind` + `write_via` + `body_sha256` nằm trong chính file (banner). 31 `fields/*.md`: front-matter, không liệt kê tập trung.
- `kinds.yaml` chỉ giữ: danh sách CURATED + binding schema. (reviewer-1)

### D4 — Write-Router `kb_route.py`: GIỮ (giá trị cao, rủi ro thấp). *(tinh chỉnh hợp đồng)*
- Read-only classifier. Output JSON. `classify --type X --format json`, `check-path <file>`. Exit ≠0 khi type lạ (chống misroute âm thầm). Dùng chung classifier với guard.

### D5 — Self-learning: `fact_key` + `content_hash` là LINCHPIN. *(net-new, v0 thiếu)*
- Mỗi record thêm: `content_hash=sha256(normalize(type|topic|content))`, `fact_key` (định danh chủ thể ổn định, vd `formula:TD_Metrics_Wide.a9`, `glossary:Doanh thu`, `convention:precedence.BC_over_DB`), `supersedes/superseded_by`, `attested_by`, `verify_ref`, `source` (phân biệt `probe:auto` vs người).
- **Dedup** (lúc add): trùng `content_hash` → `rejected_dup`; gần-trùng cùng `fact_key` (Jaccard token ≥0.9) → cảnh báo/merge.
- **Contradiction** (lúc promote): cùng `fact_key`, `content_hash` khác, formula normalize khác ⇒ mâu thuẫn ⇒ promote PHẢI từ chối trừ khi `supersede`.
- **Supersede** = append + lật trạng thái, KHÔNG xóa (audit "vì sao đổi, khi nào"). (reviewer-2)

### D6 — Promote-gate THEO LOẠI (bỏ one-size `verify_ref`). *(đổi)*
| type | evidence bắt buộc | auto? |
|---|---|---|
| fact (cấu trúc) | rebuild SHA chứa nó | auto nếu có SHA + qa pass |
| formula_correction | bằng chứng live (executePreview/flowSQL) hoặc rebuild SHA | auto nếu có |
| correction (người) | provenance người/owner (identity+source) | auto nếu provenance hợp lệ |
| glossary_term / convention | **`attested_by` (vai owner) + nguồn định nghĩa** | KHÔNG auto |

- *Lý do:* gate phải đòi *đúng loại bằng chứng*; cái không kiểm-live-được cần người ký. Second-LLM KHÔNG đủ cho claim ngữ nghĩa (failure tương quan). (reviewer-2)

### D7 — Drift sensors: UPSERT + debounce + storm-breaker (không append thô). *(đổi)*
- Bảng drift (SQLite, mutable) khóa `drift_key=sha1(probe|target|normalized_obs)`. Trùng → upsert `hit_count/last_seen`, KHÔNG tạo record mới.
- Debounce: phải thấy ≥2 lần liên tiếp mới emit `open` (chống 401 transient).
- Cooldown `suppress_until`; circuit-breaker: 1 run mở >K drift mới → emit 1 `drift:bulk_divergence` + halt per-item.
- Auto-resolve: sau rebuild, drift nào `expected` đã khớp KB → `resolved_stale`.
- Live probe **hoãn** tới khi owner login; đêm nay chỉ làm interface + test fixture. (reviewer-2)

### D8 — "Bám kịp OAC" cần CADENCE re-extract, không chỉ event. *(bổ sung)*
- Probe over known-objects KHÔNG phát hiện được object NET-NEW (dataset thứ 64). Cần re-extract toàn phần định kỳ (deterministic rebuild) để diff {added/removed/changed} → incorporate qua rebuild, ghi CHANGELOG.
- **Freshness SLA gate trong QA**: `validate_kb/qa_full` phải **FAIL (không SKIP)** khi `EXTRACT_DATE` quá hạn SLA, và S2 (so live) phải chạy được trong CI. (reviewer-2)
